REMOTE SYNC 비개발자 사용 가이드
===============================

이 가이드는 소스 코드를 빌드하지 않고 GitHub Release 압축 파일을 사용하는
방법을 설명합니다.

먼저 역할을 확인하세요
----------------------

Remote Sync는 서버와 클라이언트가 함께 동작합니다.

  서버 컴퓨터
    파일 이력과 백업 데이터를 보관합니다. 한 곳에서 계속 실행합니다.

  클라이언트 컴퓨터
    Codex 또는 Claude worktree를 선택하고 서버로 백업합니다.
    백업할 컴퓨터마다 sync-agent를 하나씩 실행합니다.

릴리즈 압축 파일 하나에는 아래 프로그램이 모두 들어 있습니다.

  sync-agent
    일반 사용자가 실행하는 클라이언트입니다.

  sync-server
    서버 관리자가 실행하는 서버입니다.

  sync-migrate
    서버 데이터베이스를 준비하거나 갱신하는 관리자 도구입니다.

일반 사용자는 sync-server와 sync-migrate를 실행하지 않아도 됩니다.


1. 내 컴퓨터에 맞는 파일 받기
-----------------------------

아래 공식 페이지에서 최신 릴리즈를 엽니다.

  https://github.com/hawoond/remote-sync/releases/latest

컴퓨터에 맞는 파일 하나를 받습니다.

  Apple Silicon Mac
    remote-sync_*_darwin_arm64.tar.gz

  Intel Mac
    remote-sync_*_darwin_amd64.tar.gz

  일반적인 64비트 Windows
    remote-sync_*_windows_amd64.zip

  ARM Windows
    remote-sync_*_windows_arm64.zip

  일반적인 64비트 Linux
    remote-sync_*_linux_amd64.tar.gz

  ARM Linux
    remote-sync_*_linux_arm64.tar.gz

Mac 종류는 Apple 메뉴 > 이 Mac에 관하여의 칩 또는 프로세서 항목에서
확인할 수 있습니다. Windows 종류는 설정 > 시스템 > 정보 > 시스템 종류에서
확인할 수 있습니다.


2. 다운로드 파일 확인하기
-------------------------

같은 릴리즈 페이지에서 SHA256SUMS.txt도 받습니다. 터미널 또는 PowerShell에서
압축 파일이 있는 폴더로 이동한 뒤 아래 명령을 실행합니다.

  macOS
    shasum -a 256 remote-sync_*.tar.gz

  Windows PowerShell
    Get-FileHash .\remote-sync_*.zip -Algorithm SHA256

  Linux
    sha256sum remote-sync_*.tar.gz

표시된 긴 문자열이 SHA256SUMS.txt의 같은 파일명 옆 문자열과 같아야 합니다.
다르면 파일을 실행하지 말고 삭제한 뒤 공식 릴리즈 페이지에서 다시 받으세요.


3. 압축 풀기
------------

다운로드한 파일을 더블 클릭해 압축을 풉니다. 압축을 푼 폴더 전체를 원하는
위치로 옮길 수 있지만, 폴더 안의 파일을 따로 분리하지 마세요.

주요 파일은 다음과 같습니다.

  QUICKSTART_KO.txt
    가장 짧은 실행 순서입니다.

  USER_GUIDE_KO.txt
    지금 읽고 있는 상세 가이드입니다.

  remote-sync.env.example
    클라이언트 설정 예시입니다.

  Start Remote Sync.command / Start Remote Sync.cmd /
  start-remote-sync.sh
    운영체제별 클라이언트 실행 파일입니다.


4. 서버 관리자에게 연결 정보 받기
--------------------------------

일반 사용자는 서버 관리자에게 아래 값을 받아야 합니다.

  SYNC_SERVER_ADDRESS
    서버 주소와 포트입니다. 예: sync.example.com:8443

  SYNC_DEVICE_TOKEN
    이 컴퓨터만 사용하는 비밀 인증 값입니다.

  SYNC_FOLDER_ID
    백업 이력이 저장될 서버 폴더 ID입니다.

한 컴퓨터의 SYNC_DEVICE_TOKEN을 다른 컴퓨터에 복사하지 마세요. 컴퓨터마다
별도 기기로 등록해야 합니다. 토큰이 노출되었다면 서버 관리자에게 새 기기
등록을 요청하세요.


5. 클라이언트 설정하기
----------------------

1) remote-sync.env.example을 복사합니다.

2) 복사한 파일명을 정확히 remote-sync.env로 바꿉니다.

3) 메모장이나 텍스트 편집기로 remote-sync.env를 엽니다.

4) 서버 관리자에게 받은 세 값을 입력합니다.

     SYNC_SERVER_ADDRESS=sync.example.com:8443
     SYNC_DEVICE_TOKEN=서버에서_받은_기기_토큰
     SYNC_FOLDER_ID=서버에서_받은_폴더_ID

5) SYNC_WORKTREE는 처음에는 비워 둡니다.

     SYNC_WORKTREE=

   프로그램이 찾은 Codex와 Claude worktree 중 하나를 직접 선택할 수 있습니다.
   선택한 폴더를 다음에도 사용하려면 나중에 표시된 ID 또는 절대 경로를
   SYNC_WORKTREE에 저장하세요.

6) 일반적인 TLS 서버에서는 아래 값을 false로 유지합니다.

     ALLOW_INSECURE=false

   같은 컴퓨터에서 시험하는 로컬 서버처럼 신뢰할 수 있는 테스트 환경에서만
   서버 관리자의 안내에 따라 true를 사용하세요.

7) 파일을 저장합니다. remote-sync.env에는 비밀 토큰이 있으므로 메일,
   메신저, 공개 저장소로 공유하지 마세요.


6. 클라이언트 시작하기
----------------------

macOS
  "Start Remote Sync.command"를 더블 클릭합니다.

Windows
  "Start Remote Sync.cmd"를 더블 클릭합니다.

Linux
  터미널에서 아래 명령을 실행합니다.

    ./start-remote-sync.sh

번호 목록이 나타나면 백업할 worktree 번호를 입력하고 Enter를 누릅니다.
worktree가 하나뿐이어도 사용자가 직접 선택해야 합니다.

터미널 창이 열려 있는 동안 Remote Sync가 실행됩니다. Ctrl+C를 누르거나
창을 닫으면 종료됩니다. 컴퓨터를 다시 시작한 뒤에는 실행 파일을 다시
열어야 합니다.


7. 운영체제 보안 경고
---------------------

이 릴리즈는 코드 서명이나 공증이 되어 있지 않습니다.

macOS에서 열 수 없다는 경고가 나오면
  SHA-256 값을 먼저 확인합니다. Finder에서
  "Start Remote Sync.command"를 Control-클릭하고 열기를 선택한 뒤 다시
  열기를 선택합니다.

Windows SmartScreen 경고가 나오면
  SHA-256 값을 먼저 확인합니다. 공식 릴리즈에서 받은 파일이 맞을 때만
  추가 정보 > 실행을 선택합니다.

운영체제의 보안 기능 전체를 끄지 마세요.


8. worktree가 보이지 않을 때
----------------------------

Remote Sync는 Codex와 Claude가 만든 Git worktree만 자동으로 표시합니다.
목록이 비어 있으면 다음을 확인합니다.

  - Codex 또는 Claude에서 작업 폴더를 먼저 만들었는지 확인합니다.
  - 프로그램을 종료하고 다시 실행합니다.
  - 직접 선택한 폴더의 절대 경로를 remote-sync.env의
    SYNC_WORKTREE에 입력합니다.
  - 일반 폴더가 아니라 실제 Git worktree인지 확인합니다.

선택한 worktree가 삭제되거나 이동되면 Remote Sync는 대량 삭제로 처리하지
않고 안전하게 중지됩니다. 새 위치를 다시 선택하세요.


9. 백업 복원하기
----------------

복원은 기존 파일과 섞이지 않도록 새 빈 폴더를 대상으로 실행하세요.
기본값은 서버의 최신 이력을 복원합니다.

macOS 터미널
  ./"Start Remote Sync.command" restore --target "$HOME/remote-sync-restore"

Windows PowerShell
  & ".\Start Remote Sync.cmd" restore --target "$HOME\remote-sync-restore"

Linux 터미널
  ./start-remote-sync.sh restore --target "$HOME/remote-sync-restore"

복원이 끝나기 전에는 대상 폴더의 파일을 수정하지 마세요. 오류가 발생하면
대상 폴더를 그대로 둔 상태에서 서버 관리자에게 터미널에 표시된 오류 내용을
전달하세요. 기기 토큰은 오류 화면과 함께 전달하지 마세요.


10. 다른 컴퓨터 추가하기
------------------------

각 컴퓨터는 별도 기기로 등록해야 합니다. 서버 관리자는 기존
restore-admin 기기에서 짧은 수명의 일회용 등록 토큰을 만들 수 있습니다.
새 컴퓨터는 그 토큰으로 등록하고 자신만의 device_token과 folder_id를
발급받습니다.

일반 사용자는 서버 관리자에게 "새 기기 등록"을 요청하면 됩니다. 기존
remote-sync.env 파일이나 기존 기기 토큰을 그대로 복사하지 마세요.
관리자용 정확한 명령은 README의 "다른 기기 등록" 항목에 있습니다.


11. 서버 운영자 안내
--------------------

서버는 한 대만 준비하면 여러 클라이언트가 연결할 수 있습니다. 서버에는
PostgreSQL과 백업 파일을 저장할 디스크가 필요합니다.

가장 간단한 설치 방법은 Docker입니다.

1) Docker Desktop 또는 Docker Engine을 설치합니다.

2) 릴리즈 페이지의 Source code 압축 파일을 받아 풉니다.

3) macOS/Linux 터미널 또는 Windows WSL에서 소스 폴더로 이동합니다.

4) 아래 명령을 실행하고 데이터베이스를 선택합니다.

     ./scripts/init-env.sh

   처음 시험할 때는 "Bundled PostgreSQL"을 선택하는 것이 가장 간단합니다.
   이미 관리 중인 PostgreSQL이 있으면 "External PostgreSQL"을 선택하고
   연결 주소를 입력할 수 있습니다.

5) 서버를 시작합니다.

     ./scripts/docker-compose.sh

6) 상태를 확인합니다.

     ./scripts/docker-compose.sh ps

생성된 .env 파일에는 초기 관리자 기기 정보와 비밀 값이 들어 있습니다.
안전한 곳에 보관하고 공개하거나 일반 사용자에게 그대로 전달하지 마세요.

기본 Docker 설정은 안전을 위해 127.0.0.1에만 연결되고 로컬 시험용
ALLOW_INSECURE=true를 사용합니다. 다른 컴퓨터나 인터넷에서 연결하려면
서버 관리자가 TLS 인증서, 방화벽, 공개 주소를 먼저 구성해야 합니다.
ALLOW_INSECURE=true 상태로 서버를 공용 네트워크에 노출하지 마세요.

서버 중지:

  ./scripts/docker-compose.sh down

이 명령은 기본적으로 DB와 백업 볼륨을 보존합니다. 데이터가 필요할 때
--volumes 옵션을 사용하지 마세요.


12. 자주 발생하는 문제
----------------------

"Remote Sync configuration was not found"
  실행 파일과 같은 폴더에 remote-sync.env가 있는지 확인합니다.
  remote-sync.env.txt처럼 확장자가 추가되지 않았는지도 확인합니다.

"connection refused", "deadline exceeded", 시간 초과
  서버가 실행 중인지, 주소와 포트가 맞는지 서버 관리자에게 확인합니다.

"Unauthenticated", "PermissionDenied"
  기기 토큰 또는 폴더 ID가 잘못되었거나 폐기된 상태일 수 있습니다.
  서버 관리자에게 새 기기 등록을 요청합니다.

인증서 관련 오류
  임의로 ALLOW_INSECURE=true로 바꾸지 말고 서버 관리자에게 TLS 서버 이름이나
  CA 파일이 필요한지 확인합니다.

실행 창이 바로 닫힘
  터미널 또는 PowerShell에서 실행 파일을 실행하면 오류 내용을 읽을 수
  있습니다. 비밀 토큰을 제외한 오류 메시지를 서버 관리자에게 전달하세요.
